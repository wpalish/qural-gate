# QuralGate 0.1

Оригинальный sandbox по направлению reference10 Vapi: опубликованный типизированный контракт → синтетические аргументы → точная диагностика/решение → один ручной результат. Никаких внешних инструментов, Vapi API, LLM, голоса или звонков не выполняется.

## Запуск

Node.js >=24.15 <25, сторонних зависимостей нет. Сначала задайте собственный пароль14–200 символов в WORK_ADMIN_PASSWORD; WORK_ADMIN_USER меняет имя первого администратора (по умолчанию admin).

```sh
PORT=8850 PUBLIC_ORIGIN=http://127.0.0.1:8850 npm start
npm test
```

HOST по умолчанию127.0.0.1, DATABASE_PATH по умолчанию.data/workspace.sqlite. Env не сбрасывает пароль существующего пользователя. Не храните пароль/базу в Git. Для внешнего сервера нужны отдельные HTTPS, резервирование и эксплуатационная проверка; это не поставлено.

24 теста: [доказательства](docs/verification.json), [браузер](docs/browser-proof.json), [источник](docs/reference-audit.md), [границы](PRODUCT.md).

## Рабочий процесс

1. Admin создаёт контракт с описаниями RU/KK и явной моделью read/write/blocked. Это ручная классификация, не обнаружение побочных эффектов.
2. Задаёт1–20 входных и1–20 выходных полей. Поддержаны text/integer/boolean, обязательность, границы чисел/длины. Optional можно пропустить; null не соответствует типам. Сторона/источник поля после создания сохраняются.
3. Проверяет и публикует точный снимок версии. Черновик может не иметь описаний/полей; публикация требует полный контракт. Дубликат версии запрещён даже после архива. Поздние правки не меняют публикацию.
4. Сотрудник проверяет вымышленные JSON-аргументы и явно сохраняет пример. Invalid сохраняется denied с диагностикой. Validread разрешён в модели; validwrite ждёт другогоadmin; blocked запрещён. Плоский JSON, неизвестные/повторные decodedключи/массивы/вложения запрещены. Типы не преобразуются; числа разбираются по стандартуJSON, включая экспоненту.
5. Другойadmin один раз разрешает/отклоняет write_model с основанием. Автор не может одобрить себя. До решения результата нет.
6. Только автор allowedзапроса один раз вручную вводит синтетический результат по выходной схеме и основание. Неверный результат получает отказ без записи. Текущий статус, исходная диагностика, решение и результат видны раздельно.

Клиент не назначает автора/время/решение/снимок. Все команды сверяют общую revision и новый UUIDrequestKey вBEGINIMMEDIATE; конфликтует и несвязанная правка. Повтор ключа — отказ, не молчаливый успех. Preview/hash не обязательны HTTP и не доказывают человеческого одобрения. При ошибке UI сохраняет ввод; автоматического повтора/слияния нет.

Архив контракта/публикации закрывает новые запросы; старые review/ack доступны по точному снимку. Pending/allowed запрос нельзя скрыть архивом. Нет отмены, повторного открытия или переноса автора. Все сотрудники читают общую область, tenant-изоляции нет. Admin не обходит owner-only результат.

## Хранение и пределы

JSON/hash не подписаны: согласованность не подлинность/исторические права. Backup исключает аккаунты/auth/audit; restore только в пустую область. HTTPJSON2МБ, каждое rawJSONполе8000знаков после обрезки внешних пробелов. Полную SQLite базу резервировать согласованно отдельно. Нет UI сброса пароля/отзыва сессий.

Это узкая собственная схема, не общий JSONSchema/Vapiwebhook. Нет enum/regex/сложенных типов/форматной/семантической проверки. Корректный тип не доказывает правдивость результата или качество контракта. Нет сетевых endpoints, APIключей, реальных данных, выполнения, внешней записи, сообщений, платежей или договоров. Модельное разрешение не предоставляет реальных прав. Публичного серверного размещения/нагрузочного/полного внешнего security/mobile/touch/screenreaderаудита нет.

Переиспользована собственная оригинальная Node/SQLite-инфраструктура; предметные правила, интерфейс и тесты QuralGate отдельные. Код MIT. Чужие закрытые исходники/бренды не копировались. Подтверждённых клиентов и выручки нет.
